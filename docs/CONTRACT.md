# The frozen contract

**Contract version 1.** This document specifies, bit for bit, the three things PLAN.md
§5.8 requires be pinned before any Rust exists: the **PRNG**, the **draw procedure**, and
**`state_hash()`**. It is the gate between Phase 1 and Phase 2.

Why it has to come first: differential testing needs an oracle, and two *equally correct*
implementations of "shuffle a deck" or "sample an unseen card" produce different — still
perfectly legal — trajectories. Without this document, a Python/Rust mismatch is
indistinguishable from a Python/Rust *bug*, and the entire port loses its safety net.

Machine-checked companion: [`tests/golden/contract_vectors.json`](../tests/golden/contract_vectors.json),
regenerated by `uv run python tools/gen_vectors.py --check`. Every claim below that can be
reduced to bytes has a vector there.

> **Changing anything here is a versioned event.** Bump `CONTRACT_VERSION` in
> `ticket_to_ride/engine/contract.py`, run `tools/gen_vectors.py --write`, and accept that
> every replay recorded under the old version is now unreplayable. Replays carry the
> version so they fail loudly rather than silently replaying a different game.

## 0. Index conventions

Frozen, because they appear in every serialized byte.

| Thing | Index |
| --- | --- |
| City | position in `RawMap.cities`, **sorted ascending by Python string order** |
| Color | position in `RawMap.color_names`, sorted ascending (USA: black, blue, green, orange, purple, red, white, yellow = 0..7) |
| Card type | color index for colored cards; **`n_colors`** for the locomotive (USA 8, mini 6) |
| Segment required color | color index, or **255 = gray** ("any single color") |
| Segment | position in `RawMap.segments`, sorted by `(city_a, city_b, length, color)` with `city_a < city_b` |
| Ticket | position in `RawMap.tickets`, sorted by `(city_a, city_b, points)` with `city_a < city_b` |

The locomotive is **not** always card type 8. TTR-mini has six colors, so its locomotive is
card type 6. Hard-coding 8 works on the USA map and silently corrupts mini.

Ordering is *derived by the generator*, never taken from file order, so re-transcribing a
map with its rows in a different sequence produces byte-identical output.

`DATA_HASH` is blake2b-128 over the canonical text encoding in `tools/gen_board.py`
(`canonical_bytes`), and is stamped into every replay: a board edit makes old replays fail
loudly instead of quietly replaying a different game.

- USA: `1e5e154018541e483aba9c4ba702396c`
- mini: `103c6ccf956f42fa082881b0b3e9f9f9`

## 1. The PRNG — PCG-XSH-RR 64/32

State is two `u64`s, `(state, inc)`, with `inc` always odd. This is O'Neill's `pcg32`,
transcribed from the reference `pcg_basic.c` with no modifications.

```text
next_u32(rng):
    old       = rng.state
    rng.state = (old * 6364136223846793005 + rng.inc) mod 2^64
    xorshift  = (((old >> 18) xor old) >> 27) mod 2^32
    rot       = old >> 59                          # top 5 bits
    return ((xorshift >> rot) | (xorshift << ((-rot) mod 32))) mod 2^32
```

```text
seed(initstate, initseq):
    rng.state = 0
    rng.inc   = ((initseq << 1) | 1) mod 2^64
    next_u32(rng)
    rng.state = (rng.state + initstate) mod 2^64
    next_u32(rng)
```

Two things a port gets wrong quietly:

- **The output permutes the *old* state**, not the newly advanced one.
- **`(-rot) mod 32`, not `32 - rot`.** They agree for all rotations except `rot == 0`,
  where `32 - rot` shifts by 32 and (in C) is undefined behaviour. `test_rot_zero_branch_is_exercised`
  asserts the golden vectors actually cover that case.

**Reference vector** (from upstream `pcg32-demo`, so a port can be checked against O'Neill
rather than against us) — `seed(42, 54)` then six draws:

```text
a15c02b7 7b47f409 ba1d3330 83d2f293 bfa4784b cbed606e
```

### 1.1 Bounded draws

```text
below(rng, bound):            # requires bound >= 1
    threshold = (2^32 - bound) mod bound
    loop:
        r = next_u32(rng)
        if r >= threshold: return r mod bound
```

Exactly uniform: the threshold discards the shortest prefix of the range that leaves an
exact multiple of `bound`. Plain `next_u32() mod bound` is biased, and worst precisely for
the large bounds we use (shuffling 110 cards). **Lemire's multiply-shift bounded generator
is faster and equally unbiased, and produces different values — it is not a permitted
substitution.**

### 1.2 Shuffle

```text
shuffle(rng, a):
    for i = len(a) - 1 down to 1:
        j = below(rng, i + 1)
        swap(a[i], a[j])
```

**Descending.** Ascending Fisher–Yates is equally correct, equally uniform, and produces a
*different permutation from the same stream*. The direction is contract, not style.

### 1.3 Seed streams

One `seed` in the config; every other stream is **derived, never drawn**:

```text
derive(root, *parts) -> (initstate, initseq):
    h = blake2b-128()
    h.update(u64_le(root mod 2^64))
    for part in parts:
        h.update(0x1f)
        h.update(utf8(part)  if part is text
                 u64_le(part) if part is an integer)
    d = h.digest()                      # 16 bytes
    return (u64_le(d[0:8]), u64_le(d[8:16]))
```

The `0x1f` separator is load-bearing: without it `("ab", "c")` and `("a", "bc")` hash to
the same stream.

Streams used by the engine, all rooted at the game's `seed`:

| Stream | Purpose |
| --- | --- |
| `("env", "deck")` | the train-car deck permutation, materialized at construction |
| `("env", "tickets")` | the ticket deck permutation, materialized at construction |
| `("env", "reshuffle")` | seeds the `rng` field carried in `State`; used only by reshuffles |

Agents get `("agent", seat, game_id)`; workers get their own. **The engine never touches
global `random`/`np.random`**, which is the precondition that makes mirrored paired
evaluation possible at all.

## 2. The draw procedure

### 2.1 The deck is a pre-materialized permutation

At construction the full deck is built in **canonical order** — `cards_per_color` copies of
color 0, then color 1, … then `locomotives` copies of the locomotive (USA: 12×8 + 14 = 110
entries) — and shuffled once with the `("env", "deck")` stream. Drawing is a cursor:
`deck[cursor]`, `cursor += 1`. The consumed prefix is retained, not erased.

Sampling lazily from card *counts* plus an RNG is distributionally identical for play and
is tempting because clones get smaller and reshuffles get free. **It silently destroys
paired evaluation**: if agent A draws 3 cards and agent B draws 5, the two mirrored games
realize *different shuffles* and the whole variance-reduction scheme evaporates with no
error anywhere. Materializing makes environment randomness a pure function of the seed,
independent of agent behaviour, at a cost of 110 bytes in a ~545-byte state.

A `deck_counts()` view is derived for determinization sampling and for exact chance
probabilities in `EXPLICIT` mode. It is a *view*; it is never the source of a draw.

### 2.2 Setup, in order

1. **Deal hands in per-seat blocks**, not round-robin: seat 0 takes the first
   `initial_hand` cards off the deck, seat 1 the next, and so on. (Physical dealing is
   round-robin; the two are distributionally identical and this one is simpler to port.)
2. **Then** flip 5 face-up, `faceup[0]` first.
3. Run the locomotive flush check (§2.5).
4. **Seats take their opening ticket offer and choose their keeps in seat order.** Seat 0
   draws `initial_ticket_deal` off the top, keeps at least `initial_ticket_keep_min`, and
   returns the rest to the bottom in ascending offer index; then seat 1, and so on.
   Returned tickets therefore reach the bottom in (seat, offer index) order, and replays
   are exact.

   Physically the offers are dealt and chosen simultaneously. Dealing one seat at a time
   gives every seat exactly the cards it would otherwise have received — the ticket deck is
   long enough that a return never wraps back into a later seat's deal, which
   `test_enough_tickets_for_a_full_table` enforces per map — and because keeps are secret
   and no seat observes another's choice, sequentializing the *choice* is
   information-equivalent. **This is the one documented rules deviation.**
5. An offer that admits exactly one legal keep mask (one ticket left in the deck, or a
   forced `keep >= offer size`) is resolved immediately rather than being asked. This is
   the same rule the mid-game `DRAW_TICKETS` action uses.

### 2.3 Drawing a card

`draw()` returns the card at the cursor and advances it. If the cursor is at the end:

- if the discard pile is non-empty, **reshuffle** (§2.4) and draw from the new deck;
- otherwise the draw **fails** and returns nothing.

Reshuffling is **lazy — at draw time, not eagerly when the cursor reaches the end.** Doing
it eagerly makes "deck empty, discards available" and "deck and discards both empty"
indistinguishable, and those two states have different legal actions.

Turn structure for `DRAW`:

- Taking a **face-up locomotive as the first card ends the draw immediately** (one card
  that turn).
- A face-up locomotive may **never** be taken as the second card.
- A locomotive drawn **blind** is an ordinary card; the turn continues.
- The taken slot is refilled **before** the second draw, and the refill may itself be a
  locomotive — which the rule above then makes untakeable.
- If no second card is obtainable at all, the turn simply ends after one card. The engine
  never constructs a node with zero legal actions.

### 2.4 Reshuffle

The discard pile is *counts*, not an order — discard order is never observable. Rebuild a
list in **canonical order** (all of card type 0, then type 1, …), shuffle it with the
`State.rng` stream, install it as the new deck, reset the cursor to 0, and zero the
discard counts.

`State.rng` is seeded from `("env", "reshuffle")` and is advanced by *nothing else*, so a
game that never exhausts the deck never touches it.

### 2.5 The locomotive flush

Whenever 3 or more of the 5 face-up cards are locomotives, all five are discarded and five
new ones dealt — and the replacement can itself contain 3 locomotives, so it **cascades**.
Checked after setup and after every refill.

> **The guard is mandatory.** With 14 locomotives in a 110-card deck, an all-locomotive
> available pool loops forever. Flush only when
> `nonloco(remaining deck) + nonloco(discard) >= 3`, and cap the cascade at
> **10 iterations** with a deterministic bail-out (stop flushing; leave the display as it
> is). This is the most common hang bug in TTR implementations, and the assertion that
> catches it — *never 3+ locomotives face-up unless the guard blocked the flush* — is the
> one most engines lack.

### 2.6 Refill and short displays

Empty slots are refilled in **ascending slot index**, at four points and no others: after
the initial deal, after a face-up card is taken (before the second draw), after a flush,
and **at the end of every turn**.

The end-of-turn refill is what stops a short display from becoming permanent. A claim moves
its payment into the discard, so cards can become available again — but if every slot is
already empty, nobody can *take* a face-up card, and a take is otherwise the only thing
that triggers a refill. Without this the display would stay empty for the rest of the game
with a full discard pile sitting next to it.

When the deck and the discard pile are both empty the display legitimately holds fewer
than 5 cards; empty slots are `-1` and are untakeable. When every pool is empty, drawing is entirely illegal — and if a seat then has
no affordable route and no ticket to draw, it plays the explicit `PASS`. **If every seat
passes consecutively the state is frozen: terminate and score**, or the engine hangs.

### 2.7 The ticket deck

A **ring buffer with head and length**, because ticket order *is* observable in one
direction: returned tickets go to the bottom and can come back around. Drawing takes from
the head; returning appends at `(head + len) mod capacity`. Draw `min(deal, remaining)`;
with an empty ticket deck the action is illegal; with exactly one left the forced keep is
auto-resolved rather than burning a network evaluation on a one-way decision.

## 3. `state_hash()` and `position_hash()`

Both are **blake2b-64** (bare, `digest_size=8`, no key/salt/personalization) over the
canonical serialization below, read back as a little-endian `u64`.

> **Deviation from PLAN.md §5.8, deliberate.** The plan said FNV-1a-64 or xxh3. FNV-1a is a
> per-byte loop costing ~40 µs in CPython over a ~450-byte state — roughly 25× everything
> else `state_hash()` does — and the differential harness calls it after *every* step of
> 100k games. blake2b is stdlib, runs at C speed (~1 µs), has a mature Rust crate, and is
> already the project's hash for `DATA_HASH` and seed derivation, so there is one primitive
> instead of two. Collision probability over a nightly run's ~15M digests is ~6e-6 either
> way.

### 3.1 Canonical serialization

Fixed field order, no padding, little-endian for multi-byte integers. `n` is the player
count and `T` the ticket-deck capacity; both are implied by the game's configuration, so
the encoding is unambiguous without length prefixes.

| Bytes | Field |
| --- | --- |
| 1 | `CONTRACT_VERSION` |
| 1 | `n_players` |
| 1 | `phase` |
| 1 | `current_player` |
| 1 | `draws_left` |
| 1 | `final_left` (255 = end not triggered) |
| 1 | `pass_streak` |
| 2 | `turn` |
| `n_segments` | `seg_owner` (255 = free, 254 = closed by the 2–3P double-route rule) |
| `n × n_card_types` | `hand`, seat-major |
| `n` | `trains` |
| `2n` | `score`, signed |
| `4n` | `tickets`, one bitmask per seat |
| 2 | `deck_cursor` |
| 2 | `deck_len` |
| `deck_len` | `deck` — **the whole permutation, consumed prefix included** |
| `n_card_types` | `discard` counts |
| 5 | `faceup`, signed, −1 = empty |
| 1 | `tdeck_head` |
| 1 | `tdeck_len` |
| `T` | `tdeck` ring, in physical index order |
| `n × n_card_types` | `certain` — public knowledge of each hidden hand |
| `n` | `unknown` — each seat's count of blind-drawn cards |
| 1 | `offer_len` |
| 3 | `offer` (255 = empty), the pending ticket offer |
| 8 | `rng.state` |
| 8 | `rng.inc` |

The per-player DSU is **excluded**: it is a cache, fully derivable from `seg_owner`, and
including it would let a pure-performance change to the union-find move the hash.

### 3.2 `position_hash()`

The same bytes, with `rng.state`, `rng.inc`, **and the consumed deck prefix**
`deck[0:cursor]` zeroed. Cards already drawn are in hands, on the table, or in the discard,
so two states that differ only in *which order* those cards were dealt are the same
position — that is exactly the transposition MCTS wants to merge. `state_hash()` keeps
them, because for differential testing "identical game" means identical down to the
unrealized future.

## 4. Replay format

```text
(CONTRACT_VERSION, DATA_HASH, rules_hash, n_players, seed, u16 actions[], final_hash, final_scores)
```

~500 B/game, ~150 MB per million games with zstd. `replay()` asserts `DATA_HASH` and
`CONTRACT_VERSION` match and that the final `state_hash()` reproduces. Details in
`ticket_to_ride/engine/replay.py`.

## 5. What is *not* frozen here

- **Rule variants** (`RuleConfig`) — hashed into `rules_hash` and carried by replays, but
  free to grow.
- **The observation encoding** — versioned separately by `OBS_VERSION` and expected to
  churn; see PLAN.md §8.2.
- **The action space** — versioned by `ACTION_SPACE_VERSION`.
- **Anything derived** — adjacency, buckets, distance tables, the DSU. All are pure
  functions of the frozen data and may be reorganized freely for speed.
- **Determinization** (`resample_from_infoset`) — a *sampler*, not a draw. It never
  advances `State.rng` and never touches the materialized permutation, so two
  implementations may legitimately produce different particles. It is validated against
  the public state by `assert_consistent`, not against another implementation.

## 6. What this document does **not** specify: `chance_mode = EXPLICIT`

Recorded here because it is a **gap in the contract, not merely unimplemented code**, and
the distinction decides who has to fix it.

§2.1 says the `deck_counts()` view "is a *view*; it is never the source of a draw" — which
is precisely what an explicit chance node would make it. And §3.1's serialization has no
field for a pending chance event: no phase value, no "which event is owed, for how many
cards". So explicit mode cannot be implemented against this document as written. It needs
either new serialized state (a `CONTRACT_VERSION` bump, invalidating every recorded replay)
or a demonstration that the pending chance is derivable from the existing fields.

Consequently **Phase 2's exit criterion is amended: sampled mode only** (PLAN.md §14 says
"both chance modes"). `ChanceMode::Explicit` and `chance_mode="explicit"` exist as declared
values that construction refuses, with that reason in the error rather than a bare
`NotImplementedError`.

When it is built, the order is forced: **Python first, then Rust, then the harness sweeps
both.** Building it in Rust first would mean writing the reference implementation in the
language the reference is used to check.
